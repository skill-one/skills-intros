# sales-enablement (`coreyhaines31/marketingskills/sales-enablement`)

## whitebox

- 先查产品上下文文件(.agents/product-marketing.md 或 .claude/ 路径或旧文件名),有则先读,只追问缺失信息
- 确认四项上下文:价值主张与差异化、销售模式、所需物料类型与阶段、现有物料状况
- 按物料类型匹配内置框架:销售演示 10-12 页故事线、一页纸五段式、异议应对五字段、演示脚本分场景计时等
- 填框架出稿,全程受四条原则约束:销售员的语言、按人设/阶段定制、3 秒可扫读、每个卖点落到业务结果
- 按该物料的既定格式交付(如异议文档=表格、演示稿=逐页大纲+讲稿);需更深模板时加载 references/ 文件

- 上下文先行:按 .agents/ → .claude/ → 旧命名顺序检查上下文文件,读过的不再问,只针对缺口提问,省去重复问答
- 框架驱动生成:不凭空发挥,每种物料有固定模板(如异议应对固定五字段:原话/背后顾虑/回应思路/证据/跟进问题),套用户上下文填充
- 人设矩阵切换 + 外部依赖声明:按买家类型查表定侧重(技术买家重架构/安全/集成,经济买家重 ROI/回收期/风险,champion 重内部说服弹药);唯一外部依赖是按需加载的 references/ 本地参考文件与 Introw 集成(仅限合作伙伴销售场景),不调用任何外部模型 API
