# offers (`coreyhaines31/marketingskills/offers`)

## whitebox

- 先读上下文: 检查 .agents/product-marketing.md 是否存在, 有则直接吸收, 只追问文件里没覆盖的信息
- 定位问题: 确认业务类型 (服务/课程/教练/信息产品/高价 B2B), 把用户现有 offer 用大白话写下来 — 名称、价格、交付物、保证、截止时间
- 诊断: 给价值方程四个杠杆各打 1-10 分, 最低分即瓶颈; 再对照六组件清单查缺失或偏弱项
- 动手改: 每轮只修一个杠杆/组件, 按需读取对应参考文档 (如 guarantee-design.md、bonus-stacking.md) 起草新方案
- 交付: 诚实预测提升幅度 (单组件改动 10-40%), 页面文案、定价结构等非本职问题转介关联技能

- 价值方程是核心分析器: Value = (梦想结果 × 达成可信度) ÷ (时间延迟 × 付出牺牲); 用户说"该降价"时, 被重译为"该抬分子或压分母" — 价格只是对比项, 不是价值本身
- 两层校验: ① 六组件完整性检查 (核心交付物/赠品堆叠/保证/稀缺紧迫/命名/价格与付款结构), 缺一即标记为弱项; ② 输出前过禁用词过滤 — 禁"革命性/秘密/限时却无期限/无依据的'价值$X'"等夸大措辞
- 无外部模型 API 依赖, 全靠本地文件 + 路由: 按场景加载 references/ 下 8 个参考文档 (价值方程、offer 解剖、保证设计、赠品堆叠、稀缺紧迫、格式手册、SaaS 专案、案例); 自助式 SaaS 让位给 pricing 技能, 销售页归 copywriting, 上线时刻归 launch
