# error-handling-patterns (`wshobson/agents/error-handling-patterns`)

## blackbox

**function**: 帮你的程序在出错时不崩溃、不装死: 我能把裸奔的代码改造成"出了问题也知道怎么办"的健壮代码, 还能分析线上报错并给出修复方案。

- input: 一段没有做任何错误处理的代码 (如"读取文件 → 处理数据", 遇到文件不存在就直接崩), output: 改进后的同一段代码: 文件缺失、数据异常等都有明确处理, 报错信息直接告诉用户"哪个文件没找到、该怎么办", 而不是一屏天书
- input: 一句线上问题描述, 如"支付接口一抽风, 用户下单就全失败", output: 问题分析 + 带自动重试和"降级"逻辑的修复代码 (重试: 失败了自动再试几次; 降级: 服务不可用时先给用户一个"稍后补单"的兜底, 而不是直接报错)
- input: "我的 API 出错时返回的东西五花八门, 前端根本没法判断", 加上接口代码, output: 一套统一的错误规范 + 改好的接口代码: 所有错误都返回固定格式 (什么错、为什么、错误编号), 前端拿到就能识别和处理
