# architecture-patterns (`wshobson/agents/architecture-patterns`)

## blackbox

**function**: 帮你设计或整理后端代码的"骨架": 把业务规则和数据库、网页接口这些外围代码分清楚, 让项目改起来不头疼、测起来不用连数据库。

- input: 一段新服务的需求描述, 如「帮我搭一个用户注册微服务, 用 PostgreSQL 存储」, output: 一套可直接开工的项目代码: 分层清晰的目录结构 + 核心业务逻辑, 附带不用启动数据库就能跑的单元测试 (自动化检查代码是否正确的测试)
- input: 一个业务逻辑和数据库操作、网页接口代码搅在一起的后端项目, output: 重构后的代码: 业务规则独立成层, 数据库等外部依赖被隔离在边缘, 并附一份「原来哪段代码挪到了哪里」的对照说明
- input: 报错信息或困扰描述, 如「use_cases 和 adapters 互相导入报错 / 测试必须连上真实数据库才能跑」, output: 问题诊断 + 修好的代码: 理清模块间的依赖方向消除循环导入, 或用内存版替身替代数据库让测试秒级跑完
