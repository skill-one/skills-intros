# python-design-patterns (`wshobson/agents/python-design-patterns`)

## blackbox

**function**: 帮你看住 Python 代码的结构：拆开纠缠不清的大段代码，并为新功能给出最简单、日后好改好测的设计方案。🧹

- input: 一个 800 多行、什么都干的 Python 类文件, output: 一份拆分后的代码：每个文件只负责一件事，并附一句「为什么这样拆」的说明
- input: 两个长得很像的函数代码 + 提问「要不要合并成一个抽象基类？」, output: 一个明确的结论：现在先不合并（或立刻合并），加上 2~3 条理由和风险提示
- input: 一段新功能的想法，比如「要加一个能导出 JSON、CSV、Excel 的报表功能」, output: 一份组件划分方案：该建哪几个类、各自管什么、互相怎么传数据，而不是塞进一个类里
- input: 一段代码 + 提问「为什么我的测试这么难写？」, output: 指出代码里哪几处让测试写不动（如数据库连接写死在函数里），并给出改写后的可测试版本
