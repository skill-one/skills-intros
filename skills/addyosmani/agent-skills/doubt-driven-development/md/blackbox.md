# doubt-driven-development (`addyosmani/agent-skills/doubt-driven-development`)

## blackbox

**function**: 在你的方案、代码或结论"定下来"之前,我当那个专门找茬的审查者:动手前就把隐患挑出来,而不是上线后再补救。

- input: 一段写好的代码(或文件路径),外加一句"它应该做到什么", output: 一份挑刺报告:列出没覆盖的情况、会出错的具体场景、藏着的坑,并按"必须改 / 可接受 / 虚惊一场"分类;需要改的直接给修改后的代码
- input: 一个还没动手的方案,如"我打算给系统加一层缓存", output: 一份风险评估:这个方案在哪些情况下会失效、漏考虑了什么,以及动手前建议先解决哪几条
- input: 一句断言,如"这样改是安全的,不会影响老用户", output: 审查结论:给出具体反例,或明确说"仔细查过但没找到漏洞"——只会报问题,不会说客套话
