# git-workflow-and-versioning (`addyosmani/agent-skills/git-workflow-and-versioning`)

## blackbox

**function**: 帮你把代码改动管理得井井有条：分成小步、清晰的存档点（git 提交），并在发布时定好版本号、打标签、写更新日志。

- input: 一个改了一堆代码、没提交、乱成一团的项目文件夹, output: 拆成一组干净的 git 提交：每条提交只做一件事，说明写得清楚，每条都能单独撤销或回退
- input: 一条需求，如「给注册功能加个手机号验证」, output: 改好的代码 + 格式规范的提交记录，并附一份改动清单：改了哪些文件、刻意没碰哪些文件、有什么需要你注意的
- input: 「项目要发个新版本了」, output: 版本号建议（如 1.4.0 还是 2.0.0）+ 打好标签的发布点 + 一份给人看的更新日志，按「新增/修复/废弃」分组，用户一眼看懂这次升级影响什么
