# spec-driven-development (`addyosmani/agent-skills/spec-driven-development`)

## blackbox

**function**: 在你动手写代码之前,先把你的想法变成一份双方都认可的需求文档 (写清楚做什么、做到什么程度算完),避免做完才发现方向错了。

- input: 一句模糊的想法,如「我想做个记账 App」, output: 先列出我做的假设 (如:网页版还是手机版?) 请你纠正,然后给你一份需求文档:目标、验收标准、哪些事必做/要先问你/绝不碰
- input: 一句没法执行的要求,如「把页面弄快一点」, output: 几条可验证的具体指标,如「打开时间 < 2.5 秒、数据加载 < 0.5 秒」,并和你确认:这是不是你要的「快」?
- input: 一个混着多个功能的大需求,如「要做用户注册、支付、邮件通知和数据报表」, output: 一张模块地图表格:拆成哪几块、谁依赖谁、建议先做哪块;你确认后再逐块出需求文档,而不是一口气混在一起写
