# frontend-design (`anthropics/skills/frontend-design`)

## whitebox

- 读需求, 先钉住主题、受众和页面的首要任务; brief 没写清就自行拟定并向客户确认
- 第一遍: 起草紧凑设计计划 (令牌系统) — 4~6 个命名色值、字体及角色、布局概念 (一句话 + ASCII 线框)、设计原则
- 把计划逐条对照「AI 生成页面通用套路」清单自查, 像默认模板的部分必须改; brief 明确指定的风格除外
- 确认计划足够独特后, 严格按修订后的计划写代码
- 自我批判收尾: 能截图就截图审查, 「出门前摘掉一件配饰」, 并守住质量底线 (响应式 / 键盘焦点可见 / reduced motion / 可访问性)

- 解析→转换: 把 brief 压缩为 color / type / layout / principles 四要素的令牌化计划, 先规划后编码; 字体选择与行宽、行高尺度参照《The Elements of Typographic Style》的默认指导
- 前置校验: 内置反模板清单逐条对照 — 奶油底 + 赤陶色 (#F4F1EA / #D97757)、深底荧光绿、报纸风、SaaS 圆角卡片、全大写眉标、中点连接符等「生成腔」, 命中即改为针对本 brief 的有意选择
- 后置校验与依赖: 成品必须过质量底线 (移动端响应式、键盘焦点可见、尊重 prefers-reduced-motion、视觉可访问), 自查靠截图; 本 skill 无任何外部依赖 — 不调用库、构建工具或模型 API, 截图仅为环境可选能力
