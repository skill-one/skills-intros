# dbs-goal (`dontbesilent2025/dbskill/dbs-goal`)

## whitebox

- 读取全部上下文（当前消息、历史对话、附件、已确认信息），提取目标卡字段：交付物、使用对象、范围、规格、完成条件、约束。
- 按清晰度选处理路径：A 可直接执行 / B 有阻塞性缺口 / C 表达仍是模糊愿望 / D 当前目标疑似只是手段。
- 路径 B/C/D 时跑条件测试（可指物、完成边界、语义做工等），每次只问信息增量最高的 1 个问题，等回答后重新判断。
- 用户补充或提取完成后进入路径 A：输出简洁目标卡，标出低风险假设，不再追问。
- 按最短够用格式输出（目标卡 / 单一缺口提问 / 完整审计报告），结束审计。

- 语义做工检测：判断一个词是否改变交付物、使用对象、范围格式、执行路径、验收结果、资源风险边界六项之一，据此把词分类为「在做工／暂未做工／需要定界」，决定哪些信息直接提取、哪些必须追问。
- 提问纪律（四项内部检查）：提问前先确认答案是否已在上下文、能否安全推断、不同答案是否改变交付物/路径/验收、此刻提问是否有决策价值——任一前项为「是」或后项为「否」就取消提问，保证不问已给过的信息。
- 无外部依赖：全程纯提示词方法，不调用任何外部工具、库或模型 API，仅靠读取上下文 + 语言模型自身推理与文本生成完成；唯一的「外部检查点」是结尾提示需确认环境已安装 /dbs。
