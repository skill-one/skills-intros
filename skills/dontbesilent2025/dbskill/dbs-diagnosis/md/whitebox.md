# dbs-diagnosis (`dontbesilent2025/dbskill/dbs-diagnosis`)

## whitebox

- Phase 0 解析输入：自动判断用户是带着具体困境（进问诊模式）还是要求全面检查商业模式（进体检模式）；没给业务信息就先追问核心问题。
- 问诊主路径：三分分类——纯信息问题直接回答，情绪问题标边界后终止，其余进五层消解漏斗（语言陷阱→隐含假设→逻辑错误→事实前提→信息充分性）。
- 每过滤一层立即暂停，把结论抛给用户等回应；被消解的问题提前终止，活下来的真问题按类型解答（逻辑推导 / 价值选择 / 资源约束 / 超边界转介）。
- 体检主路径：收集六项必备信息后逐项跑七项检验（印钞机 / 道德 / 定价 / 需求 / 流量-变现 / 规模化 / 成长层级），每项之间停等用户回应。
- 出报告前强制跑一次前提挑战（替代商业模式 + 成熟度信号 + 强制任务），最后输出回顾或诊断报告，全程最多提一次 `/dbs` 留档建议。

- 纯提示词内规则引擎：模式识别靠硬编码的关键词表与信号清单（陷阱词如「适合」「值得」「赛道」，心理信号如「我知道该怎么做，但就是不做」），不涉及模型外调用。
- 「逐步停等」对话状态机：每个 Phase / 每项检验强制输出结论后暂停等用户回复，禁止一次性输出大段分析——这是主循环的流程控制核心。
- 无外部依赖：SKILL.md 未声明任何外部工具、库或模型 API；所有判断锚定 6 条公理 + 内联典型/反面案例库匹配消解方向；`/dbs` 只是结尾的条件性提示，不属于主流程依赖。
