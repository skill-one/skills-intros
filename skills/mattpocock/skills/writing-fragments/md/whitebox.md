# writing-fragments (`mattpocock/skills/writing-fragments`)

## whitebox

- 用户抛出想写的话题; 若没给文件路径, 只问一次存哪, 之后全程记住
- 进入'拷问式'访谈: 连续追问用户想写的内容, 不给大纲、不搭结构
- 碎片从对话双方嘴里冒出来 (金句、小场景、半截念头、一个能扛起全文的'关键词')
- 写入前先重读文件 (防用户手动改过), 然后把新碎片静默追加到 markdown 文件, 用 --- 分隔
- 回到第 2 步循环追问→追加, 直到会话结束

- 纯探索模式 (pure explore): 唯一产出物是 fragments——标准是'作者自己看得懂 + 算得上好文字', 不要求冷读者能理解; 明确禁止提前分阶段、列大纲、搭文章结构
- 追加式文件协议: 首次写入只放一个 H1 工作标题; 正文无小标题、无标签、无排序, 仅按添加顺序用 \n---\n 分隔; 只追加不覆盖; 用户的'删掉最后一个''把那句改锋利点'是一等指令, 就地改指定碎片
- 关键词挖掘 (leading word): 当对话绕着同一个想法打转, 就推动铸造一个词来命名它——这是最值钱的碎片, 后续结构、过渡、标题全靠它
