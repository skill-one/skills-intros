# writing-shape (`mattpocock/skills/writing-shape`)

## whitebox

- 完整读取用户传入的 markdown 素材文件 (只读, 永不编辑原材料)
- 与用户确定前置条件: 读者开场已具备哪些概念, 未列出的概念必须在文中先铺垫后使用
- 起草 2~3 个指向不同论点/角度的开头, 用户选定或组合出一个, 该开头决定全文后续必须做什么
- 进入逐段循环: 自问"读者下一步需要听什么"→ 从素材中取料 → 与用户争论该块用什么形式 (段落/列表/表格/引用块/代码块) → 敲定后立即追加写入文章文件
- 循环直到用户宣布完成; 若用户未指定文章保存路径, 开工前先问一次并记住

- 概念接地 (grounding) 校验: 维护运行中的"已接地"清单, 每个概念要么是读者自带的前置, 要么由先前段落引入; 后续段落只准依赖已接地概念, 否则先补铺垫或调整顺序, 再决定前置与文中铺垫的边界
- 素材当矿场而非剧本: 片段可拆分、合并、改写以融入段落, 但全文保持一个声音; 素材缺料时明确指出缺口 ("此处需要例子, 要么现在给我, 要么砍掉这节")
- 增量写盘: 每敲定一块立即追加, 不攒批; 每次写入前先从磁盘重读文章文件 (用户可能在回合间手动改过), 改写段落时只动那一段。无外部工具/库/模型 API 依赖 — 全靠对话中的用户确认与文件读写
