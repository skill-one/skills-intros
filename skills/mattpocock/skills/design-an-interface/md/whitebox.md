# design-an-interface (`mattpocock/skills/design-an-interface`)

## whitebox

- 收集需求: 向用户问清模块要解决什么问题、调用方是谁、关键操作、约束条件、内外边界
- 并行生成设计: 通过 Task 工具同时派出 3+ 个子代理, 给每个分配不同约束, 收回各自统一格式的设计稿
- 逐个展示设计: 依次呈现每个方案的接口签名、调用方实际用法、内部隐藏了什么
- 对比方案: 从接口简洁性、通用vs专用、实现效率、深度、易正确使用vs易误用五个维度, 用散文形式对比 (不用表格)
- 综合定稿: 追问用户哪个方案最贴合主用例、值得吸收其他方案的哪些元素, 最优解常是多方案组合

- 并行子代理 + 约束差异化: 每个子代理被强制指派一个不同约束 (如"最多 1-3 个方法" / "最大化灵活性" / "为最常见场景优化" / "借鉴某范式或库"), 并按统一输出格式 (接口签名/用法示例/隐藏内容/权衡) 产出; 目的是强制方案彼此截然不同, 防止雷同。依赖外部工具: Task 工具 (派发子代理)。
- "Design It Twice" 评价框架: 理论来源是《A Philosophy of Software Design》的深度模块理论——小接口藏大复杂度为优 (deep module), 大接口薄实现为劣 (shallow); 据此用五个维度做对比, 且只比接口形状, 明确不写实现、不以实现工作量评估。
- 需求先行、无自动假设: 设计前必须通过提问清单 (问题/调用方/操作/约束/隐藏内容) 收集需求, 缺口由用户回答补齐, 而非凭空猜测。
