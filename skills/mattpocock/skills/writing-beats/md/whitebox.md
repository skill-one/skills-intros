# writing-beats (`mattpocock/skills/writing-beats`)

## whitebox

- 收下原始素材 markdown 文件; 若用户没说文章存哪, 问一次并记住路径
- 与用户敲定前置知识: 哪些概念读者进门就懂 (已'落地'), 其余必须由 beat 先建立后才能用
- 写 2~3 个候选起始 beat, 先展示给用户 (不写文件); 用户选一个
- 只把选中的 beat 写进文章文件, 然后从磁盘重读全文, 再给 2~3 个候选下一步 beat (每个标注它解锁什么)
- 循环写 beat 直到旅程自然收尾; 素材有剩料是常态, 不追求用完

- Grounding 守门: 每个概念被 beat 依赖前必须已'落地'——要么是前置知识, 要么被之前的 beat 建立; 维护已落地清单, 每落一个 beat 就更新; 候选 beat 只从当前集合出发, 捡到'缺前置'的 beat 时, 要么前面补一个铺垫 beat, 要么把它升格为前置知识
- 素材开采: 原始素材只当采石场, 可改写/拆分/重组/引用; beat 按它做的那个'动作'定大小 (一句话到几段皆可), 若需要 5 段加小标题, 判定为两个 beat 粘连, 拆开
- 文件纪律: 每次只追加一个 beat, 绝不提前写; 每次写入前从磁盘重读全文, 绝对保留用户改动, 用户大改某个 beat 会改变后续走向; 全程无外部库/模型 API 依赖, 仅本地 markdown 文件读写 + 与用户对话
