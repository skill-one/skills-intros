# domain-modeling (`mattpocock/skills/domain-modeling`)

## blackbox

**function**: 在你讨论项目业务时,把含糊、打架的术语问清楚、定下来,并整理成术语表和关键决策记录,保证「说的」和「代码做的」是一回事。

- input: 一个含糊的词,比如「账户」, output: 一句追问:「你说的是注册的客户 Customer,还是登录账号 User?这俩不是一个东西」,并给出一个明确的规范叫法
- input: 你的说法 + 相关代码,比如「订单可以部分取消」+ 代码文件, output: 指出矛盾:代码里取消是整单退,你说的却是部分退——逼你当场拍板哪个是对的
- input: 讨论中敲定的术语或大决定,如「核销 = 扣掉已用额度」或「改用事件溯源存订单」, output: 落地成文档:术语更新进 CONTEXT.md 术语表;难回头的大决定写成一份 ADR 决策记录(为什么这么选、放弃了什么)
