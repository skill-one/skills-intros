# polish (`pbakaus/impeccable/polish`)

## whitebox

- 强制前置：先调用 /impeccable 拿设计原则与上下文收集协议；若尚无设计上下文，必须先跑 /impeccable teach，并确认质量档位（MVP 还是旗舰）
- 发现设计系统：搜索 token 定义、组件库、风格指南，记录既有约定与偏差（硬编码值、重复造的组件）
- 抛光前评估：确认功能已完整（未完成不抛光）、有无需保留的已知问题、距上线多久（决定时间预算）
- 系统性抛光：按 12 个维度逐一处理（对齐间距→排版→色彩对比→交互状态→动效→文案→图标→表单→边界态→响应式→性能→代码质量），再完整过一遍抛光清单
- 终验与清理：亲自操作、真机测试、覆盖全部状态；然后把自造组件换回共享组件、删孤儿代码、合并 token、消除抛光引入的重复

- 上下文协议门禁：一切工作前必须经 /impeccable 的 Context Gathering Protocol 拿到设计上下文，不满足即中断先补课；外部依赖就是 /impeccable 这个 skill 本身，不调用任何模型 API
- 设计系统锚定：所有修复以现有 token/组件库为基准——硬编码值换成 token、重复实现换成共享组件；无设计系统时退化为对齐代码库可见约定；对比度按 WCAG AA 校验，同一颜色全站含义一致
- DevTools + 真机双重验证：抛光质量靠浏览器 DevTools 验证（网格覆盖层查对齐、检查器量间距、多断点测试），收尾以真机实际操作为准而非仅 DevTools；动效硬约束（60fps、只动 transform/opacity、尊重 prefers-reduced-motion）作为校验项
