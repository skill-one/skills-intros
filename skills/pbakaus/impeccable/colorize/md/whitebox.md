# colorize (`pbakaus/impeccable/colorize`)

## whitebox

- 强制前置: 调用 /impeccable 技能获取设计原则、反模式与 Context Gathering Protocol; 若无设计上下文则先跑 /impeccable teach, 同时收集现有品牌色
- 评估用色机会: 分析现状 (纯灰/单一弱点缀色/可增值点) 与色彩能带来语义、层级、分类、情绪、引导的位置; 代码推断不出就直接问用户
- 制定策略: 在中性色之外选 2~4 个颜色, 按 60/30/10 确定主色/辅色/点缀色, 并规划每个颜色出现的位置与理由
- 分维度系统上色: 按语义状态→强调色→背景表面→数据可视化→边框→排版→装饰逐层注入, 颜色统一用 OKLCH 定义
- 平衡与验证: 核对 60/30/10 占比、WCAG 对比度、色盲兼容性, 确认层级/语义/吸引力达标且颜色不过载

- 外部依赖 /impeccable 技能 (强制前置): 提供设计原则、反模式与 Context Gathering Protocol; 无法从代码库推断的信息必须向用户澄清, 不臆测
- OKLCH 色彩空间: 感知均匀 (亮度等步长视觉上等距), 用于生成和谐色阶; 附带硬约束——中性色禁用纯灰、大面积禁用纯黑纯白、禁止默认紫蓝渐变
- 双重校验: 注入时执行 WCAG 合规检查 (文本 4.5:1、UI 组件 3:1、色彩不得作为唯一指示, 需图标/标签/图案配合) + 收尾五项验证 (层级/语义/吸引力/可达性/不过载), 任一不过即调整
