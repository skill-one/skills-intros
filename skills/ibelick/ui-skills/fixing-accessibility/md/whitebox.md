# fixing-accessibility (`ibelick/ui-skills/fixing-accessibility`)

## whitebox

- 触发: 无参数时把规则集作为约束套用到本会话所有 UI 工作; 带文件参数时进入逐条审查模式
- 对照 9 类规则 (可访问名称 → 键盘 → 焦点与对话框 → 语义 → 表单 → 播报 → 对比度 → 媒体 → 工具边界) 逐行检查 HTML 结构与 ARIA 属性
- 按三段式输出报告: 引用违规代码片段原文 → 一句话说明为何重要 → 代码级修复建议
- 落地修复时只做最小化、定点改动, 不重写大段 UI

- 纯规则清单静态审查: 判断依据全部来自内置规则表与常见修复模板 (icon 按钮补 aria-label、div 按钮换原生 button、表单错误用 aria-describedby 关联等), 无外部工具/库/模型 API 依赖
- 优先级驱动排序: 9 类规则分 1~9 级, 报告顺序与修复顺序由 critical 级 (1~3 级: 名称、键盘、焦点、工具边界) 优先决定
- 最小改动约束: 优先用原生 HTML 语义而非叠加 ARIA; 复杂控件 (菜单/对话框/下拉) 推荐成熟的可访问组件实现而非自造行为; 明确禁止重构无关代码、禁止迁移 UI 库
