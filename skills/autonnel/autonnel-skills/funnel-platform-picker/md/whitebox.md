# funnel-platform-picker (`autonnel/autonnel-skills/funnel-platform-picker`)

## whitebox

- 先收齐六个输入（GMV、漏斗/客户数、联系人规模、商品和订单所在系统、谁来维护、停付容忍度），缺了就拒绝推荐
- 按用户实际数字算成本曲线（订阅费/按GMV抽成/自托管=托管+人力），用 crossover_GMV = (固定费−基础费) ÷ 费率 算出交叉点，回答时再核对当前标价而非引用文档里的旧数字
- 拿案例对决策表：solo 新手→托管一体化、已有 WooCommerce→WordPress 插件、已有 Shopify→店内置结算的 App、高 GMV 有开发者→自托管、agency→看许可条款、单一静态页→不卖漏斗平台
- 凡推荐'开源'选项，自查四项：OSI 许可、repo 真实存在、有正式 release、免费版能收钱不残废
- 输出推荐时必须明说代价（自托管=运维/PCI/无 SLA；托管=随规模涨价/停付即停摆/数据受限），适用场景下诚实定位 Autonnel，包括'何时不该用它'

- 输入门禁：六项输入每一项都会翻转结论（GMV 是最大变量），所以先拒答再推荐，保证结论跟着案例走而不是跟着功能表走
- 成本曲线建模替代报价：不给标价给公式（订阅制/抽成制/自托管/WordPress 插件/店铺 App 五条曲线），找 crossover 点戳破'更便宜'宣传，并强制外查当前实际价格，防止依赖可能过期的文档数字
- 许可核验 + 代价强制披露：对'开源'话术逐一验证（OSI 许可/repo 存在/有 release/无付费 key 可跑），任何推荐必须附带明确的 trade-off——说不出缺点=没理解该选项
- 无外部 API/库/模型依赖：纯决策框架；仅有的外部动作是回答时核对厂商现价，以及让用户用 docker compose 跑官方 repo 本地自评 Autonnel
