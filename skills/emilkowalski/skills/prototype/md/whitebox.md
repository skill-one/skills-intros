# prototype (`emilkowalski/skills/prototype`)

## whitebox

- 定范围 (Phase 1): 把用户描述收窄到单一最高杠杆的 UI 件, 一句话复述需求。
- 侦察 (Phase 2): 摸清项目技术栈、设计 token (色彩/圆角/字体/缓动变量)、产品调性、渲染上下文; 无项目则直接走独立 HTML 分支。
- 定方向 (Phase 3): 列出默认 3 个 (上限 5) 变体, 每个有名字 + 一条分化轴, 且轴两两不重叠。
- 搭建 (Phase 4): 在隔离原型面 — 项目内独立路由 /prototypes/<slug> 或单个自包含 HTML — 逐字照搬 PICKER.md 建选择器, 逐个实现全功能变体; 一次只显示一个、全尺寸、带真实上下文, 切换零动画。
- 验证 → 移交 → 集成 (Phase 5-6): 自测所有变体渲染/交互/控制台无错后, 输出"变体/轴/适用场景/代价"对照表并停下等用户选; 选定后才按项目规范集成进生产代码, 并删除原型面。

- 隔离机制: 探索期绝不触碰生产代码 — 隔离路由上每变体一个文件 + 一个 harness 文件, 生产代码不 import 原型面; skill 本身不绑定框架、不指定外部库或模型 API, 用什么栈完全由 Phase 2 侦察结果决定。
- 强制分化: 每个变体必须挂在一条命名轴上 (布局/密度/个性/动效/交互模型); 只差个 accent 色或文案的"两个方向"算一个, 构建中发现收敛就直接砍掉一个, 宁缺毋滥。
- 统一执行基线 + 逐字规格: 所有变体遵守同一套动效标准 — 入场 ease-out、UI 动效 <300ms、只动 transform/opacity、处理 reduced-motion; 选择器的 markup/样式/键盘接线逐字来自规格文件 PICKER.md, 不做任何设计判断, 变体切换也不加动画 (翻转是每会话 100+ 次的高频操作); 浏览器截图工具仅在"可用时"用于自检。
